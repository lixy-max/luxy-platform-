# 界面自动化探针（playwright-core + 本机 Edge）

**为什么需要**：本项目前端是 6k+ 行单文件，改动后的效果此前只能靠人肉点。
聊天里那 5 个 bug（按钮点了没反应、占位符当文件名请求 400、状态变量未声明…）
本来都能被这套探针抓到。

**为什么用 playwright-core**：它**不下载浏览器**，直接驱动系统里已装的 Edge。

## 用法（Windows 侧，因为 node 在 Windows）

```powershell
cd <仓库路径>\tools
npm install playwright-core        # 一次性，约 1 个包
node ui_probe.js                   # 跑交互断言，输出 ✓/✗ 与捕获到的报错
node ui_shot.js                    # 只截图，供人工或视觉模型查看
```

前置：前端已在 `http://127.0.0.1:8080` 提供服务（`bash scripts/run.sh`）。

## 它断言什么（会随版本增补）

- 能进入「📝 编辑工作流」页
- 预设下拉有选项；载入后画布出现节点；步骤清单渲染
- 点画布节点 -> 参数面板出现字段与必填提示
- 「➕ 添加步骤」-> 弹窗可见、列出全部工具、选中后弹窗关闭且画布新增节点
- 拖绿点(`.doc-dot-out`)到另一个节点 -> 参数里出现 `{{steps.N.字段}}` 引用
- **全程捕获 console.error / pageerror / HTTP 4xx+**，任何一条都算失败信号

## 注意

- 用 `executablePath` 指向 Edge；若路径不同请改脚本顶部常量。
- 它是**探针**不是正式测试：跑完看 ✓/✗ 与错误列表即可。

## 全站自检 + 内置 Agent 真跑

```powershell
node ui_full_check.js       # 逐页巡视 9 个页面，然后驱动内置 Agent 跑一个真实任务
```

它会：
1. 逐个点开 9 个页面，记录「元素数 / 按钮数 / 文本长度 / 该页新增报错」并截图；
2. 切到 🤖 Agent 模式，选模型，发一句真实任务，轮询到 agent 返回，
   输出工具调用卡片数量与回答尾部；
3. 全程汇总 console.error / pageerror / HTTP 4xx+。

## 文档处理任务测试台（服务端，不依赖浏览器）

```bash
python tools/doc_task_battery.py --rounds 2     # 或 make doc-test
```

37 个用例/轮，覆盖：从 0 创建（Word/Excel）、目录页、六种语言处理（含长文分块）、
往返校验（写出去再读回来比对内容）、边界与异常、保真（数字不被精简掉）、
命名冲突、多格式与相对路径。

**2026-10 实测：真实模型下两轮各 37/37 全绿（合计 74 项，PASS 74 / CHECK 0 / FAIL 0），
两轮结果完全一致。** 产物落在 `E:\project test desktop\doc_tests\`，可直接打开核对。

约定（踩过坑后定的）：
- 三类结果分开记：PASS / CHECK（行为与预期不同，需人判断）/ FAIL（非预期异常）。
  负向用例用 `expect_raise` 标记，抛出预期异常记 PASS。
- 需要模型的工具可以打桩快速自检，但**桩必须保留与真实实现相同的入参校验**，
  否则负向用例会被桩放过去、报出假失败。
- 分块相关断言依赖输入超过 chunk_chars，用例里用 while 循环拼到 7000 字以上，
  不靠估算。
