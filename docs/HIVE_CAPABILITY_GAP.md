# 奇美拉蜂群能力差距分析：能否"自己长出手脚"？

**结论先行：技术路径可行，当前处于"半自主单机蜂巢"（约 60% 目标能力）；距离"按需自生长"还差 6 个闭环，不是缺零件，而是缺"感知缺口→获取→验证→部署→监控→固化"的自动化闭环。** 日期：2026-10-27

## 0. 先把"自己长出手脚"翻译成可验收的能力

```
用户需求 → ①察觉能力缺口（缺工具/知识/模型/数据？）
        → ②自主获取（检索开源/生成工具/训练 LoRA/搭建工作流）
        → ③沙箱验证 + 评测门禁（不达标不许上线）
        → ④热部署（新"手脚"挂载为能力节点）
        → ⑤在线监控 + 灰度 + 自动回滚
        → ⑥沉淀复用（经验/记忆/技能固化，下次更便宜更快）
```

只有 ①→⑥ 全部**自动**跑通，才算"自己长手脚"；缺任何一环，都只是"人工装配 + 自动执行"。

## 1. 现状成熟度矩阵（基于 S18–S23 实测证据）

| 能力 | 等级 | 实测证据 | 缺口 |
|---|---|---|---|
| 请求理解 / 意图 / 单层拆解 | L3 | S18 三路由 9/9 正确；subtasks 字段可用 | 只有单层路由，无多步 DAG 执行/重规划 |
| 路由决策（Local/Cloud/Sim） | L4 | 18/18 架构；guided JSON；成功率与兜底可测 | 成本/延迟感知未接入（provider 固定顺序） |
| 本地执行 + 动态 LoRA | L4 | 热加载 0.75s；并发 20/20；LRU；读写锁防 vLLM 竞态 | 仅单工蜂节点；能力标签仍是启发式 |
| 云端教师兜底 | L3 | 失败→云端 13.8s；阈值/复位；轨迹回收 | 云端只回"文本答案"，无工具调用轨迹 |
| 轨迹质检 + 自动训练 | L2 | 质检 6/6；阈值触发；真实训练 35.7s 产出 adapter | 样本仅 3~6 条；1.5B adapter 与 7B 工蜂不兼容 |
| 热部署 / 灰度 / 回滚 | L3 | shadow→评测→灰度 4.3%→active→rollback 全通 | **无自动质量监控回滚**；灰度未按用户/会话 |
| **能力缺口识别** | L1 | 缺能力时只会"转云端" | **不能输出"缺什么、怎么补"的结构化缺口** |
| **工具/工作流自创造** | L1 | 有 cloud_workflow_builder(S15)/workflow_engine 等零件 | **未接入蜂巢飞轮：检索→生成→沙箱→注册 未自动** |
| **多节点集群** | L1 | 结构支持 worker 池，但只有 1 张卡做真实工蜂 | 节点注册/容量调度/跨节点故障转移缺失 |
| **自愈 / 运维** | L2 | 审计/台账/runbook；训练 GPU 回退（3060→5060） | 无 watchdog 自动重启、无告警、无持久训练队列 |
| **长期记忆 / 经验固化** | L2 | 临时知识库（SQLite+动态 KB TTL 24h、语义检索） | 无长期 episodic/semantic 记忆、无压缩/巩固 |
| **自动灰度监控** | L1 | 手动 rollback 可用 | 错误率/延迟/质量超阈值自动回滚未实现 |
| **安全治理（自我修改）** | L1-2 | 审计/预算/台账/评审流程 | 缺审批门禁、能力沙箱、熔断/杀开关 |
| **评测与进化 KPI** | L2-3 | 架构 18/18；1242 tests；台账 62 条 | 缺"按能力"的成功率/成本/训练 ROI 追踪 |

**评级说明**：L0=无；L1=有零件/人工；L2=单点自动；L3=闭环可复现；L4=稳定+有治理；L5=全自动自进化（目标）。

## 2. 距离目标还差什么：6 个关键闭环

| # | 缺失能力 | 为什么关键 | 最小可行实现（MVP） |
|---|---|---|---|
| 1 | **能力缺口感知（Capability Gap Detector）** | 现在只会"转云"，不会"学"——不知道缺的是工具、知识、还是模型 | 任务 → 结构化缺口标签 {tool,knowledge,model,data} + 获取计划；写入能力注册表 |
| 2 | **自主获取与创造（Acquisition）** | 这是"长手脚"的核心：工具生成/开源移植/工作流搭建必须自动 | 浏览器检索开源 → 兼容性判定 → 沙箱生成/移植 → 自动测试（S15/奇美拉零件接入飞轮） |
| 3 | **沙箱验证与评测门禁（Verification）** | 没有门禁的自生长=灾难；新能力必须证明不退化 | 自动评测集生成 → 回归/质量/延迟/成本门禁 → 不达标自动丢弃 |
| 4 | **多节点部署与调度（Orchestration）** | 一张卡不可能"长手脚"；需要按需挂载新能力节点 | 节点注册/心跳/容量/成本 → 异构 GPU 调度；1.5B 小工蜂 + 7B 主工蜂 |
| 5 | **自动灰度与自愈（Canary & Healing）** | 上线后无人盯=不可控；需自动回滚/重启/降级 | 灰度指标（错误/延迟/质量）→ 超阈值自动 rollback；watchdog 自动重启；训练持久队列 |
| 6 | **安全治理与人类审批（Governance）** | "自己长手脚"必须可控：谁批准、能花多少钱、可回滚 | 审批门禁（自修改需确认）→ 预算/权限 → 能力沙箱 → 熔断/杀开关 → 全链路审计 |

## 4. 路线图（S24–S28，按依赖顺序）

| 阶段 | 目标 | 验收标准（可复现） |
|---|---|---|
| S24 | 能力缺口感知 + 工具/工作流沙箱（Gap Detector + Sandbox） | 10 个不同任务 → 缺口标签准确率 ≥80%；3 个沙箱生成/移植工具通过自动测试并注册 |
| S25 | 多节点工蜂 + 容量感知调度（Multi-node） | 1.5B 小工蜂 + 7B 工蜂跨节点路由；节点故障自动转移；并发 20 跨节点正确命中 |
| S26 | 7B QLoRA 自动训练闭环（Train→Eval→Hotload→Auto-rollback） | 7B adapter 训练成功；评测门禁通过后自动灰度；超阈值自动回滚 |
| S27 | 长期记忆 + 能力 KPI（Memory & Metrics） | 跨会话记忆召回 ≥80%；按能力统计成功率/成本/训练 ROI 看板 |
| S28 | 治理与受控自主验收（Governance + Gated Autonomy） | 自修改审批/预算/沙箱/熔断齐全；端到端"缺口→获取→验证→部署"无人值守跑通 10 次 |

## 5. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 硬件（16GB+12GB，单工蜂） | 多节点/7B 训练受限 | S25 先加 1.5B 小工蜂；7B 用 QLoRA；或按预算加卡 |
| 自修改安全 | 错误能力上线/失控 | S24 沙箱+S28 审批门禁/熔断；能力可回滚 |
| 评测不足导致过拟合 | 门禁形同虚设 | 自动评测集 + 真实任务回归 + 灰度指标 |
| 成本失控（云端 API） | 不可持续 | 预算感知路由 + 成本 KPI（S27） |
| 内存（bge-m3 2-3GB） | 后端 OOM（已实测过一次） | embedding 独立服务/默认关语义 |
| 样本不足（自动训练 3~6 条） | adapter 质量差 | 扩大轨迹采集 + 评测集 + 门禁 |

## 6. 结论

- **能否达到？能。** 所有关键零件（路由/工蜂/LoRA/云端教师/轨迹/训练/热加载/仿真/记忆）都已有可复现原型与实测数据；
- **当前不是"缺能力"，而是"缺自动化闭环"**：从"人工装配"升级为"感知缺口→自主获取→验证→部署→监控→固化"；
- **现实定位**：半自主单机蜂巢（约 60%）→ 受控自主（S28 目标 85%+）→ 全自动自进化（需更多硬件+评测治理）；
- **最短路径**：先 S24（缺口感知+沙箱）→S25（多节点）→S26（7B 训练闭环），这三步决定"长手脚"能否成立；
- **不建议**现在就追求"完全无人监督"：自修改安全 + 评测门禁 + 预算治理必须先于自动化。
