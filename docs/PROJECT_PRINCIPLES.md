# 项目原则（★ 教训固化 · 2026-10-19）

> 来源：2026-10-19 复盘。我们闭门造车三轮（~10h）+ 差点在错误方向上再投入 63h，
> 靠 2 小时查文献救回来。这两条原则就是为了不再犯。

---

## 原则一：调研先行（Research First）

### 规则
```
任何「要不要做 / 怎么做 / 期望多少收益」的决定，
必须【先查文献 + 查开源】再动手 ✓
```

### 硬性要求
| # | 要求 |
|---|---|
| **R1** | 新方向开工前，**至少 2 篇文献依据** ✓ 记入 `docs/LITERATURE_REGISTRY.md` |
| **R2** | 没有文献依据的方向 ⇒ **最多做 2 小时小验证** ✗ **不许大规模投入** ✗ |
| **R3** | 任何方案文档**必须含「文献依据」章节** ✓ 否则视为未完成 ✗ |
| **R4** | 决策要写清「依据哪篇文献的哪条结论」✓（可追溯 ✓） |
| **R5** | 每轮实验前先问：**这个方向有没有人做过？结果如何？** ✓ |

### 反例（这次踩的）
```
✗ 想要"LoRA 训练更强模型" → 直接做三轮（v3-2-0/1/2）→ 才查文献
   ⇒ 文献早说了：7B/PET 天花板=底座（Zhang ICLR 2024）✗
   ⇒ 代价：三轮白做 ~10h ✗ + 差点再投 63h ✗
   ⇒ 正确做法：开工前 2h 查文献 ⇒ 会立刻知道该转向工具调用 ✓
```

## 原则二：先找不训（Search Before Train）

### 规则
```
当用户想要一个「什么样的模型」时，
不是直接闷头训练 ✗ 而是【优先去找现成的】✓
```

### 查找优先级（从高到低）
| 顺序 | 找什么 | 理由 | 例子 |
|---|---|---|---|
| **1** | **现成模型**（HF / ModelScope 上已发布的） | 最快 ✓ 免费 ✓ | NexusRaven 7B ✓ Hammer-7B ✓ |
| **2** | **现成 LoRA**（社区训好的同能力适配器） | 即插即用 ✓ | 各种 HF LoRA ✓ |
| **3** | **现成 API/服务**（云服务直接覆盖） | 零维护 ✓ | 云模型 API ✓ |
| **4** | **提示词/检索方案**（不改模型） | **能 +36~56%** ✓（Toolshed/2510.17874 ✓） | 工具检索 ✓ 故障排查库 ✓ |
| **5** | **最后才自己训练** ✓ | 最贵 ⚠ 最慢 ⚠ | LoRA / 全参 |

### 平台落地（我们的差异化 ✓）
```
我们有【浏览器自动化】✓（web_* 工具链 ✓）
⇒ 把"找"做成平台能力 ✓：
   `search_existing_models(query)` →
     ① 检索 HF / ModelScope / GitHub（模型 + LoRA）✓
     ② 返回候选（名称/大小/许可/下载量/评测分数 ✓）
     ③ 自动对比谁最接近需求 ✓ 能不能直接用 ✓
     ④ 结论：直接用 ✓ / 试提示词方案 ✓ / 才自己训 ✓
```

### 反例（这次踩的）
```
✗ 想要"工具调用更强" → 直接自己训 LoRA ✗（三轮 ✗）
✓ 正确做法：先搜 ⇒ 发现 NexusRaven/Hammer/xLAM 三个 7B 开源模型已超 GPT-4 ✓
   ⇒ 直接下载对比 ✓ 比训练快 100 倍 ✓
```

## 原则三（衍生）：评测口径先行

```
训练/改造之前先定义「怎么算成功」✓ 否则做完也不知道好坏 ✗
```

| # | 要求 |
|---|---|
| **M1** | 指标要**具体** ✓（"工具选择准确率" ✓ 不是"总分"✗） |
| **M2** | 样本量 **n ≥ 30** ✓（12 太小 ⇒ t 不可信 ✗） |
| **M3** | 必须有 **base 对照臂** ✓（防 base 漂移误导 ✗） |
| **M4** | **环境要隔离**（快照/还原 ✓ 防状态污染） |
| **M5** | 报**均分 + 差 + t 值** ✓ 不报单一数字 ✗ |

### 反例（这次踩的）
```
✗ v3-2-2 A/B: +8.0 (t=2.09 边缘 ✓) 但【base 自己漂了 −7.5 (t=−2.30 显著)】✗
   ⇒ 优势一半来自 base 掉分 ✗ 结论不可信 ⚠
   ⇒ 原因：n=12 + 环境没隔离 + 只看总分 ✗
```
