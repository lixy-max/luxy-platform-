## 二、四个任务实测结果

### T1 噪声识别（页眉/页脚/页码/目录）—— ⚠ **67%**

| 块 | 真值 | 模型输出 | 判定 |
|---|---|---|---|
| `noise_page` | 噪声（页码 ✗） | `{"noise": true, "type": "页码"}` ✓ | ✓ 对 |
| `noise_header` | 噪声（页眉 ✗） | `{"noise": false}` ✗ | ✗ **漏判** |
| `noise_toc` | 噪声（目录 ⚠） | `{"noise": false}` ✗ | ✗ 漏判（可议 ⚠ 目录也有信息） |
| `good_para` / `good_md` / `mid_para` | 非噪声 ✓ | `{"noise": false}` ✓ | ✓ 对 |

**准确率: 4/6 = 67%**

**⇒ 结论**: → **不可靠** ✗
- **页码**能识别 ✓
- **页眉**漏判 ✗（"2026 年第三季度技术报告 · 内部资料" 它认为不是噪声 ✗）
- **⇒ 噪声识别应该【规则优先】** ✓（页码/页眉有固定 pattern：`第 X 页`、`共 X 页`、重复出现的短行 ✓）

### T2 质量评分（0-10 分，排序用）—— ✅ **有区分度**

| 块 | 分数 | 判定 |
|---|---|---|
| `noise_page` | **0** ✓ | 正确 ✓ |
| `noise_toc` | **0** ✓ | 正确 ✓ |
| `noise_header` | **5** ⚠ | 偏高 ⚠ |
| `good_para` | **8** ✓ | 正确 ✓ |
| `good_md` | **5** ⚠ | 偏低 ⚠ |
| `mid_para` | **5** ⚠ | 合理（太短 ✓） |

**⇒ 好块均分 6.5 vs 噪声均分 1.7** ⇒ **区分度有效 ✓**

**⇒ 结论**: → **可用于排序/抽样** ✓ 但**不适合做硬性过滤** ✗（个别误判 ⚠）
- **好的用法**: → 按分数排序 ✓ → **优先检索高分块** ✓ → 或 **抽样给人工看** ✓
- **不好的用法**: → `score < 3 就删` ✗（会误删 ✓）

### T3 元数据抽取（topic / section / keywords）—— ✅✅ **优秀**

```json
good_para → {"topic": "向量相似度检索", "section": "知识库构建流程",
             "keywords": ["向量","相似度","文档切分","Chroma","余弦相似度","chunk_size"]}
good_md   → {"topic": "分块策略", "section": "3.2",
             "keywords": ["结构感知切块","文档标题层级","语义完整"]}
```

**⇒ 结论**: → **直接可用** ✓✓ — 质量接近人工 ✓ 延迟 1.1-1.5 秒 ✓
- **价值**: → 检索结果可**溯源到章节** ✓（K-8 缺口 ✓）+ **topic 可做过滤** ✓

### T4 问题生成（评测集用）—— ✅✅ **优秀**

```json
good_para → ["知识库检索中，文档是如何被处理成块的？",
             "在查询时，如何确定与问题最接近的文档块？"]
good_md   → ["结构感知切块的优点是什么？",
             "无结构纯文本在进行分块时会采用什么方法？"]
```

**⇒ 结论**: → **直接可用** ✓✓ — 问题**只有该块能回答** ✓ 正是 IR 评测集需要的 ✓
- **价值**: → **P-74 的 K3（检索评估）测试集可以自动生成** ✓✓（方案里说"用云模型或本地模型"✓ → **本地模型足够** ✓）

## 四、可行性结论（**分层方案** ✓）

### ✅ 强烈推荐用本地模型（高价值 + 成本可接受）

| 任务 | 理由 | 耗时/书 |
|---|---|---|
| **T4 问题生成** | 质量优秀 ✓ 评测集必需 ✓ 无法用规则替代 ✓ | 6 分钟（可有可无 ✓ 一次生成永久复用 ✓） |
| **T3 元数据抽取** | 质量优秀 ✓ 解决溯源缺口 ✓ | 6 分钟 |
| **T2 质量评分**（抽样/排序） | 区分度有效 ✓ 用于**排序**而非删除 ✓ | 6 分钟（可选 ✓） |

### ⚠ 不推荐用本地模型（规则更好/更快）

| 任务 | 理由 |
|---|---|
| **T1 噪声识别** | **67% 不可靠** ✗ → **规则优先** ✓（页眉/页码 pattern 秒级 ✓） |
| **全量质量过滤** | T2 个别误判 ⚠ → 不能做硬过滤 ✗ → 只排序 ✓ |
| **分块** | 规则（段落/句子/标题 ✓）更好 ✗ → LLM 不需要 ✓ |
| **精确去重** | hash 秒级 ✓ LLM 无意义 ✗ |

### ❌ 明确不做

| 不做 | 理由 |
|---|---|
| ✗ 全量 LLM 清洗每一块 | 18 分钟/书 ✗ 而规则只要秒级 ✓ → 收益/成本不划算 ✗ |
| ✗ LLM 决定删块（硬过滤） | 误判会丢信息 ✗ → **只做排序/标注** ✓ 由用户决定 ✓ |
| ✗ 用 LLM 做分块 | 规则更好 ✓ LLM 慢且不稳定 ✗ |

## 五、建议的最终方案（混合 ✓）

```
入库时（用户点"上传并入库"）:
  ① 规则清洗（秒级 ✓ 必做 ✓）
     · 页码/页眉 pattern 正则删除 ✓
     · 精确去重（hash ✓）
     · 空块/超短块（<20 字）丢弃 ✓
     · 结构感知切块（Markdown 标题 / 段落 ✓）
  ② 本地模型增强（5-18 分钟 ✓ 可选 ✓ 默认开 ✓）
     · T3 元数据（topic/section/keywords ✓ 每块 1 次）
     · T4 问题生成（仅抽样 20 块 ✓ 用于评测集 ✓ 不是每块 ✓）
     · T2 质量评分（可选 ⚠ 排序用 ✓）
  ③ 入库 + 报告
     · 块数/去重数/噪声删除数 ✓
     · 质量分布 ✓
     · [预览块] [下载报告] ✓
```

**⚠ 关键设计**：
```
T4 问题生成【只抽样 20 块】✗ 不是每块 ✓
  ⇒ 评测集只需要 20-30 条测试用例 ✓（方案 K3 ✓）
  ⇒ 成本从 6 分钟降到 12 秒 ✓✓
```
