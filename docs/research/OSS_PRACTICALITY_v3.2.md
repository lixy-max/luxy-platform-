# 开源实用性报告 · LoRA 工作台 v3.2（v0.3.6）· 2026-10-19

> **一句话结论**：**这是一套"重但强悍"的论文/文档处理工作台** ✓
> 装机门槛比同类聊天 UI 高 ⚠，但**能力面（54 工具 · 文档真产出 · LoRA 训练+评估闭环 · 浏览器自动化）在开源里少见** ✓
> 实用性评分：**7.8 / 10**（对**有 GPU、要处理 Word/Excel/论文的科研/办公用户**可达 **9/10** ✓；对"只想聊天"的用户 **4/10** ✗）

## 一、目标用户与定位

### 1.1 它解决什么问题
**论文/文档处理的全链路** ✓：读取 → 分析 → 改写/纠错 → 产出 Word/Excel → 质量评估 → 用自己的数据训 LoRA

### 1.2 谁该用（✓）
| 用户类型 | 为什么适合 |
|---|---|
| **科研/研究生** | 论文分析、Word 改稿、Excel 数据表、质量台账 ✓（**这是主场景** ✓） |
| **有本地 GPU 的用户** | 7B/4B 本地跑 · 数据不出本机 ✓ 隐私友好 ✓ |
| **要训自己 LoRA 的人** | 自带**训练 + 评估闭环** ✓（同类项目大多只给训练 ✗ 不给评分 ✓） |
| **需要浏览器自动化** | 内置 13 个 browser_* 工具 ✓ 用自然语言驱动网页 ✓ |

### 1.3 谁不该用（✗）
| 用户类型 | 原因 |
|---|---|
| **只想聊天** | 比 Open WebUI / LobeChat / Cherry Studio **重** ⚠ 装它不划算 ✗ |
| **没有 Python 环境的小白** | 虽然有一键脚本 ✓ 但出错时要看日志 ⚠ |
| **纯云 API 用户** | 支持云模型 ✓ 但它的价值在**本地模型 + 文档流水线** ✓ 纯云用 Dify 更合适 ✓ |
| **要公网/多用户部署** | ✗ **无 API 鉴权**（仅本机设计 ✓）· 无 Docker ✗ 无用户系统 ✗ |

```bash
# 方式 1：Windows 双击「一键安装.bat」（三处各一份 ✓ 桌面/E:\WSL/仓库根）
```
