## 二、真正的问题（验证中暴露的 ✓ 比原假设更重要）

### P-19 ★★ 工具定义在 92 个里【大量重复】✗

抓包实测（92 个 tools 里）：
```
list_knowledge_bases  出现 3 次 ✗（内置工具 + 文档工具 + 手写 schema 各一份）
run_workflow          出现 3 次 ✗
create_workflow_config 出现 2 次 ✗
create_knowledge_base 出现 2 次 ✗
export_docx / read_docx / write_docx / read_upload / start_training … 均重复 ✗
```
⇒ 根源：三套来源被**合并**进同一个 schema ✗
   · `AGENT_TOOL_DOCS`（手写 schema ✓ 32 条）
   · 后端文档工具（33 条 ✓ `/docs/tool/list`）
   · 另一份"内置工具"兜底（description = "内置工具：xxx" ✓ 参数为空 ✗）
⇒ 影响：7B 面对【92 个含重复+空参数的函数】✗ ⇒ 选择困难 ✓ 更容易反问或乱选 ✗
⇒ 这正是 P-10（工具口径不一致）的**严重化版本** ✓
