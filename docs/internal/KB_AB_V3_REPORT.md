## 五、结论（严格按 EVAL_PROTOCOL ✓）

### 5.1 支持的陈述（有统计证据 ✓）

1. **结构感知切块显著提升检索** ✓✓
   - hit@5 **+14.0pp**（t=2.45 · p=0.014 · d=0.35 · 中等效应）
   - MRR **+20.0pp**（t=4.17 · p<0.0001 · d=0.59 · 中等效应）
   - 95% CI 均不含 0 ✓

2. **规则清洗对检索无显著影响** ✓（但完全清除了噪声 ✓）
   - hit Δ=0.000（t=0.00 · p=1.00 · CI 跨 0）
   - MRR Δ=+0.006（t=0.18 · p=0.85 · CI 跨 0）
   - ⇒ **清洗的价值不在检索** ✓

3. **答案关键词命中率全部无显著变化** ⚠
   - A/B/C = 0.313 / 0.332 / 0.301
   - 所有 t 检验均不显著 ✗
   - ⇒ **检索好了没转化成答案质量** ⚠

### 5.2 为什么清洗没提升检索（★ 关键洞察 ✓）

```
**噪声对所有文档都是相同的**（"【内部资料 · 第 N 页】2026 年第三季度技术报告 · 请勿外传"）
  ⇒ 它不提供"区分文档"的信息 ✗
  ⇒ 不改变"哪篇文档更像"✗
  ⇒ 所以 hit@5 / MRR 不变 ✓（t=0.00 铁证 ✓）

⇒ **清洗的真实价值不是"提升检索"** ✗
  而是:
  ① **让检索结果 / LLM 上下文干净** ✓（省 token ✓ 读起来不烦 ✓）
  ② **防止噪声占满上下文窗口** ✓（chunk 里 20% 是噪声 ✗）
  ③ **块预览/人看更专业** ✓
```

### 5.3 不支持的陈述

1. ✗ "清洗能提升检索" —— **本次数据显示无显著影响** ✓
2. ✗ "能提升问答质量" —— kf_rate 全部不显著 ⚠
3. ✗ "对真实 PDF 有效" —— 用的是人工注入噪声 ⚠（真实 PDF 噪声更复杂）
4. ✗ "可推广" —— 单语料 / 单 embedding / 单 LLM ⚠

### 5.4 仍存在的限制

| # | 限制 |
|---|---|
| 1 | **人工注入噪声** ⚠（真实 PDF 噪声更复杂：乱码/表格/图注/双栏） |
| 2 | 单 embedding（bge-small-zh）· 单 LLM（Qwen2.5-7B） |
| 3 | 只测 1 个语料（项目 docs） |
| 4 | 出题来自 A 组块 ⇒ **对 A 组有轻微优势** ⚠（三组用同一批问题 ✓ 算是公平 ✓） |
| 5 | **答案质量指标太粗** ⚠（关键词命中率不反映语义正确性） |
