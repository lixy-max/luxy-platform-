## 三、方案（分 4 阶段 · 每项含 收益/成本/风险/验收）

### Phase 0 · 安全 + 性能（低风险 · **~1.5 天**）
| 项 | 做法 | 收益 | 风险 | 验收 |
|---|---|---|---|---|
| **0-1 XSS 净化** | `marked` 输出过 **DOMPurify**（或自写 allowlist ✓）+ 所有模型/文件内容强制 `escapeHtml` ✓ + serve.py 加 **CSP** 头 ✓ | 🔴 消除注入 ✗ | 可能误杀 markdown 排版 ⚠ | 注入样本被拦 ✓ 现有渲染不破 ✓ |
| **0-2 CDN 本地化** | 3 个 CDN 文件放 `webui/vendor/` ✓（~60KB ✓）→ 引用本地 ✓ | 首屏 **984ms → <150ms** ✓✓ 断网可用 ✓ | 无（版本锁死 ✓） | 断网加载正常 ✓ |
| **0-3 缓存策略** | HTML 保持 no-store ✓；**vendor/*.js 加内容 hash + 长缓存** ✓；页面 JS 同 ✓ | 二次加载 < 100ms ✓ | 版本错乱 ⚠ | 刷新后不加载重复资源 ✓ |

### Phase 1 · 可维护性（中风险 · **~4 天**）
| 项 | 做法 | 风险控制 |
|---|---|---|
| **1-1 API 层** | 新建 `webui/api.js`：统一 `request(path, opts)`（超时/重试/错误 toast ✓）→ 168 处 fetch **逐步**收敛 ✓ | 每改 10 处跑一次 365 断言 ✓ |
| **1-2 模块化拆分** | `index3.html` → `core.js`（状态/路由/API ✓）+ `pages/<page>.js`（12 页 ✓）→ HTML 只剩骨架 ✓ | **一次只拆一页** ✓ 拆完跑断言 + 手工冒烟 ✓ |
| **1-3 事件委托** | 147 内联 onclick → `data-action` + 一个委托监听 ✓ | 渐进：新代码用新法 ✓ 旧代码按页迁移 ✓ |

### Phase 2 · 体验（低风险 · **~3 天**）
| 项 | 做法 |
|---|---|
| **2-1 导航分组** | 10 个二级 tab → 3 组（对话/平台/系统 ✓）或折叠 ✓ |
| **2-2 统一状态** | 抽 `ui.js`：loading / empty / error / toast 四态 ✓ |
| **2-3 a11y** | 116 个按钮补 `aria-label` ✓ + 键盘 Tab 可达 ✓ + 焦点管理 ✓ |
| **2-4 移动端** | 关键 3 页（对话/KB/浏览自动化 ✓）响应式 ✓ |

### Phase 3 · 工程化（低风险 · **~3 天**）
| 项 | 做法 |
|---|---|
| **3-1 E2E 冒烟** | 复用 Playwright（drill 跑手已验证 ✓）→ 30 条关键路径 ✓（打开/切页/发消息/工具卡/确认弹窗 ✓） |
| **3-2 性能预算** | 首屏 < 300ms ✓ 资源 < 600KB ✓ DOM < 2500 ✓（CI 断言 ✓） |
| **3-3 静态检查** | axe-core 可访问性 ✓ + 简单 lint ✓ |

## 四、明确不建议做的（✗ 附理由）

| 不建议 | 理由 |
|---|---|
| **框架重写（Vue/React）** ✗ | 9,051 行 + 365 断言全绑在原生 DOM 上 ✗ 重写风险极高 ✗ 而平台价值在 **API/工具/评估闭环** ✓ 不在前端技术栈 ✓ |
| **引入构建链（Vite/webpack）** ✗ | 单机工具 ✓ 收益 < 成本 ✓（拆成原生 ES 模块即可 ✓） |
| **换组件库/Tailwind** ✗ | 现有 CSS 变量体系已统一 ✓ 换掉需全量改样式 ✗ 无对应收益 ✓ |
| **SSR** ✗ | 无 SEO 需求 ✓ 纯工具 ✓ |

| 风险 | 概率 | 应对 |
