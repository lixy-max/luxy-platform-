## 三、LoRA 到底改了什么（行为分析 ✓）

**证据：它确实不是没生效** ✓ —— 而是**学错了方向** ✗

| 任务 | 臂A 提出工具 | 臂B 提出工具 | 变化 | 执行数变化 |
|---|---|---|---|---|
| **P1-36** | 3 | **24** | **+21** ✗✗ | 2→3 |
| **P1-27** | 3 | **22** | **+19** ✗✗ | 2→2 |
| **P1-35** | 2 | **17** | **+15** ✗ | 2→3 |
| **P1-12** | 3 | **17** | **+14** ✗ | 3→5（**还撞了超时 241s** ✗） |
| **P1-02** | 16 | **1** | **−15** ✓ | 4→1 ✓（这个反而改对了 ✓） |

### 诊断：模型学到了「多调工具 = 好」✗
- **训练数据的锅** ✗：我给每条任务的 function_call 序列是 **1-4 个** ✓
  模型学到的模式 = "回答前多调几个工具" ✗
- **反而 P1-02（该少调的）从 16 → 1** ✓ ⇒ 少数任务上确实学到"收敛" ✓
- **净效果**：工具数上去 ✓ 但 **执行数/成功率没跟上** ✗ ⇒ **没学会"调对"** ✗

## 四、失败原因（4 条，全部可验证 ✓）

| # | 原因 | 证据 | v3-2-1 修法 |

| 3 | **过拟合** ✗ | loss 6.63 → **0.0008**（430 条 × 3 epochs ✗） | 降 rank 16→8 ✓ / epochs 3→2 ✓ / 加数据 ✓ |
| 4 | **训练数据行为偏差** ✗ | 每条样本 1-4 个工具调用 ⇒ 学会"多调"✗ | 加入"该少调"的负样本 ✓ + 明确 1 个工具就够的场景 ✓ |
