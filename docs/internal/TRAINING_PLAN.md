## 四、训练配置（两套 ✓ 7B 主 / 4B 备）

### 4.1 主方案：**7B QLoRA**（质量优先 ✓）
```yaml
base_model:      Qwen2.5-7B-Instruct        # fp16 ✓ 15G
quantization:    4-bit (QLoRA)               # 训练时 ~6G ✓
lora_rank:       32                          # r=32 ✓ alpha=64 ✓
lora_alpha:      64
lora_dropout:    0.05
target_modules:  q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj
learning_rate:   1e-4                        # LoRA 常用 ✓
lr_scheduler:    cosine
num_epochs:      3
batch_size:      1  × grad_accum 8           # 有效 batch 8 ✓
max_seq_len:     4096                        # 覆盖 system prompt + 工具结果 ✓
bf16:            true
warmup_ratio:    0.05
save_steps:      100
```
**显存预估**：4-bit 底座 6G + 激活/梯度 ~4G + LoRA 参数 <1G ≈ **11~13G** ✓
⚠ **必须**：① 停 vLLM ✓（省 9.2G ✓）② 关掉 Windows 图形应用 ✓（它们可能占 1.6~8G ✗）

### 4.2 备选：**4B QLoRA**（速度快 ✓ 显存松 ✓）
```yaml
base_model:      Qwen3-4B-Instruct          # 7.6G → 4-bit ~3G ✓
其余同 7B ✓（rank 32 ✓ lr 1e-4 ✓ epochs 3 ✓ max_seq 4096 ✓）
```
**显存预估** ≈ **7~9G** ✓（更稳 ✓ 训练时间约 7B 的 60% ✓）

### 4.3 训练时间预估（单卡 RTX 5060 Ti 16G）
| 配置 | 500 条 × 3 epochs | 时间 |
|---|---|---|
| 7B QLoRA | 1500 步 ✓ | **~1.5-2.5 小时** |
| 4B QLoRA | 1500 步 ✓ | **~1-1.5 小时** |

## 五、评估方案（复用现成 A/B ✓ 这是重点 ✓）

### 5.1 设计：**同一次跑内 A/B**（不是分两次 ✗ —— P-59 的教训 ✓）
```
需要扩展跑手：把 --ab 的两臂从「闸门⑤ 开关」改成「LoRA 开关」✓
  臂 A（基线）: 不挂 LoRA（vllm:base ✓）
  臂 B（实验）: 挂新 LoRA（vllm:lora:<新名> ✓）
  每个任务连续跑两臂 ✓ 相邻时间 ✓ ⇒ run-level 漂移抵消 ✓
```
⚠ **实现**：`tools/drill_run.mjs` 已支持 `--lora` ✓ → 需加 `--ab-lora` 模式 ✓（~40 分钟 ✓）

### 5.2 判定标准（事先定好 ✓ 不事后找理由 ✓）
```
n = 50 任务（part1 ✓）· 配对 t 检验
|t| > 2 且 配对差均值 > 跨臂噪声 ⇒ **LoRA 有效** ✓ 可写进结论
|t| ≤ 2                       ⇒ **无显著提升** ✗ 照实说 ✓ 不美化 ✗
```

### 5.3 辅助指标
- **工具选择精度**（proposed_tools vs exec_tools ✓ 判分器已有 ✓）
- **合规率**（≥42 分占比 ✓）
- **判官分**（`--judge` ✓ 云模型 ✓ 需网络 ✓）
- **不调工具率**（该调没调 ✗）

### 5.4 冒烟评估（省时间 ✓）
先用 **20 任务** ✓ 快速看方向 ✓ → 有希望再跑满 50 ✓
