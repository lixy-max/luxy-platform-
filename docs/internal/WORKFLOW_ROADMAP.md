# 工作流优化与扩展方向

> 基于本会话对 `paper_lora_project` 的实际改造与实测数据整理。
> 最后更新：2026-10-05（提交 `9ff679a` 之后）

---

## 0. 本会话已完成（作为后续判断的基线）

| 方向 | 内容 | 关键实测 |
|---|---|---|
| 失败语义 | 节点失败不再静默产错：`retry`/`timeout`/`on_error`、上游缺失传播、报告警告头、`_meta.failures/degraded` | 长文失败从"静默产错"变为显式标注 |
| 知识库 | `kb_name` 支持节点显式 / 环境变量 / `auto` 自动探测（多库取最近更新的并列出候选） | 新建库无需改配置即可生效，11/11 验证通过 |
| 评测闭环 | `eval_lora.py`（有参考）+ `spot_check.py`（无参考）；三重泄漏检查（指纹 / 模板重叠 / **输入重叠**） | 发现并拦下一次真实泄漏 |
| 抽取式训练 | `build_extractive_dataset.py`：目标 100% 为原文句子；`extract_v1`/`extract_v2` | 留出论文 similarity 0.077 → **0.605**，29/30 改善 |
| 分块抽取 | 节点 `chunk_size`/`chunk_overlap`，map-reduce + 去重合并 | 4 万字论文输出 94 → **1,455** 字，事实 19/19 |
| 输出格式 | `output_format: text`（抽取式 LoRA 的正确搭配） | 节点值类型正确，不再误判 JSON 失败 |
| 默认工作流 | 接入本地抽取节点 + claims 输入瘦身 | claims 提示词 **−87%**，声明数 13 → **16**，数字证据 3 → **8** 处 |

## 1. 可靠性（"结果能不能信"）

| # | 方向 | 收益 | 成本 | 风险 | 说明 |
|---|---|---|---|---|---|
| A1 | **节点级 JSON schema 校验** | 高 | 低 | 低 | 现在只校验"是合法 JSON"。节点声明 `required_fields`，缺失即降级 —— 云端少给一个字段时不会静默通过 |
| A2 | **报告级事实回查** | 高 | 低 | 低 | 复用 `key_fact_retention`：最终报告里的数字/缩写回查抽取结果，低于阈值就加警告头。把"可溯源率"变成每次运行的显式指标 |
| A3 | **断点续跑 / 单节点重跑** | 高 | 中 | 中 | 现在任一节点失败要从头重跑（4 万字论文 3-4 分钟）。需要中间结果落盘 + 复用 |
| A4 | **无依赖节点并行执行** | 高 | 中 | 中 | `analyze_method`/`analyze_data`/`extract_claims`/`critique_analysis` 互不依赖，现在严格串行。并行后总时长近乎减半（注意 vLLM 并发与云 API 限流） |
| A5 | 云端调用确定性 | 中 | 低 | 低 | `temperature>0` 的节点补 `seed`，否则同一输入两次结果不同，评测对比失真 |
| A6 | 失败节点自动降级路径 | 中 | 中 | 中 | 例如 `analyze_method` 失败时用 `extract_dimensions.method` 兜底（并在报告里标明来源），而不是整个节点缺失 |

## 2. 成本与性能（用户当前最关心：本地推理耗时）

| # | 方向 | 收益 | 成本 | 风险 | 说明 |
|---|---|---|---|---|---|
| B1 | **分块抽取并行** | 高 | 低 | 低 | 18 块串行 60s；vLLM 本身会批处理，并发提交可显著缩短。引擎已有 `chunk_size`，加个 `chunk_workers` 即可 |
| B2 | **抽取结果缓存** | 高 | 低 | 低 | 按「文件哈希 + 抽取配置哈希」缓存。调下游提示词时不必重复抽同一篇论文（本会话反复重跑就是这种场景） |
| B3 | 云端 token 预算提示 | 中 | 低 | 低 | 调用前估算并记录每个节点的 prompt token，超阈值给提示（本会话已实测：claims 从 ~1 万降到 ~1.3 千） |
| B4 | 分块 `max_tokens` 自适应 | 中 | 低 | 低 | 现在文本节点固定 1024、aggregate 固定 4096；按块大小与任务类型自适应，避免"块大输出被截断" |
| B5 | 本地/云端任务编排 | 中 | 中 | 中 | 本地节点（免费但慢）与云端节点（快但花钱）的调度策略，例如本地跑抽取的同时云端跑维度抽取 |

|---|---|---|---|---|---|
| C1 | **多配置切换** | 中 | **极低** | 低 | 后端 `/workflow/run` 已支持 `config_name`，**前端只缺一个选择器**。可以立即做出"论文精读 / 审稿意见 / 复现清单"多套模板 |
| C2 | **Agent 工具化** | 高 | 中 | 中 | 让对话里的 Agent 能触发工作流、解释 `_meta.failures`、对比两次运行。复用现成 15 个工具框架 |
| C3 | **结果自动入库知识库** | 中 | 中 | 中 | 把抽取结果与分析报告写回 KB，形成"读过哪些论文"的积累，下次同类论文可检索历史分析 |
| C4 | 图表 / 多模态 | 中 | 高 | 高 | PDF 里的方法流程图与结果表目前完全丢失（纯文本提取）。需要视觉模型或多模态底座 |
| C5 | 报告导出 | 中 | 低 | 低 | 导出 Markdown / PDF / Word。WPS 插件已按用户要求禁用，可走独立导出路径 |

| C7 | 一键部署 / 可移植 | 中 | 中 | 中 | 目前强依赖 WSL + 手工环境（venv、vLLM 参数、模型路径）。Docker 化并把模型与配置版本绑定 |
| C8 | 工作流模板市场 | 低 | 中 | 低 | 预设模板 + 导入导出（`/workflow/config/import` 已有） |

## 4. 质量精度（按用户要求：**最后做**）

| # | 方向 | 收益 | 成本 | 风险 | 说明 |
|---|---|---|---|---|---|
| D1 | 扩论文重训 `extract_v3` | 高 | 中 | 中 | 现在只有 16 篇（12 训练 / 4 留出）。目标 40-50 篇，并做"论文级留出"，让 metrics 真正代表跨论文泛化 |
| D2 | 抽取目标加"句子 + 字符偏移" | 高 | 中 | 中 | 为 C6 打基础；也让评测能算"是否抽全了方法章节"而不是只看词面重合 |

## 5. 建议执行顺序

**第一批（纯工程、不碰模型、立刻见效）**

1. **B2 抽取结果缓存** —— 调下游提示词时不再重复抽同一篇论文（本会话反复重跑的最大时间浪费）
2. **B1 分块并行** —— 4 万字论文的本地抽取从 ~60s 降到 ~15s
3. **A4 无依赖节点并行** —— 4 个分析节点并行，总时长近乎减半
4. **C1 多配置切换** —— 后端已支持，前端加个下拉即可，立刻能出多套模板

**第二批（提升可信度）**

5. **A1 节点级 schema 校验** + **A2 报告级事实回查** —— 把"可溯源率"变成每次运行的显式指标
6. **A3 断点续跑** —— 依托 B2 的缓存机制一起做

**第三批（能力扩展）**

7. **C2 Agent 工具化** —— 让对话直接驱动工作流并解释失败原因
8. **C3 结果入库** —— 形成长期积累

**最后（按用户要求）**

9. **D1 扩论文重训** → **D2 字符偏移** → **C6 引用定位** → **D3 人工标注评测集**

## 6. 一句话判断

当前工作流已经做到"**输入真实论文 → 本地逐字抽取 → 云端结构化分析 → 中文报告**"，
且失败与降级都会显形。**下一个瓶颈不是模型质量，而是工程效率**：
同一篇论文调参要重复抽 3-4 分钟、4 个独立节点串行、失败要整条重跑。
先做第一批 4 项，用户体验会有明显变化；模型质量（D 类）放到最后。
