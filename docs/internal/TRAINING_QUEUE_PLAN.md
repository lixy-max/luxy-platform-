## 一、先回答一个关键问题：**还要不要训练？**

按**原则二「先找不训」** ✓ 必须先把这个问题答清楚 ✓：

| 我们想要的 | 现成有没有 | 结论 |
|---|---|---|
| **工具调用强** | ✅ **有**：xLAM-2-8B（98k 下载）· Hammer2.1-7B（榜单第一系）· NexusRaven-13B | ⚠ **先评测现成的** ✓ 够用就**不训** ✓ |
| 角色扮演 | ✅ 有：Hermes-3-8B · Stheno-8B | ⚠ 现有 `swk_persona_v3` 够用 ⇒ 先评测 ✓ |
| 中文/平台适配 | ⚠ 现成模型对**我们的 85 个工具**不熟 ✗ | ⚠ **可能需要小训练** ✓（这是唯一理由） |

### ⇒ 所以排期的第一件事不是训练 ✗ 是**评测现成模型** ✓
```
原则二 + 文献（Zhang: PET 天花板=底座）⇒ 
  如果现成模型已经比我们的 base 好 ⇒ 训练没有意义 ✗
  只有当「现成模型 + 我们的工具集」不匹配时 ⇒ 才值得训 ✓
```

## 三、每步具体命令（可执行 ✓）

### T-0 现成模型评测（2h）
```bash
# ① 下载（hf-mirror ✓ 我们已测通）
python tools/download_model.py Salesforce/Llama-xLAM-2-8b-fc-r   # 若无此脚本 ⇒ huggingface-cli

# ② 起 vLLM 服务现成模型（AWQ 不可 ✗ 需 fp16 ⇒ 16GB 卡只能装 8B 的 GGUF/AWQ ✗）
#    ⚠ 现实：xLAM-2-8B fp16 = 16GB ✗ 装不下 ⇒ 只能用 GGUF(ollama) 或 量化 ✗
#    ⇒ 替代方案：用 llama.cpp/ollama 跑 GGUF ✓（工具调用 schema 需适配 ⚠）

# ③ 评测（若起得来）
powershell -File E:\WSL\_check\ab_t0.ps1   # 32 条 × 2 臂（我们base vs 现成）

# ④ 判分
python scripts/tool_metrics.py --runs ... --eval-set docs/EVAL_SET_32.json --compare t0_base t0_off
```

⚠ **现实约束（诚实说 ✓）**：
```
16GB 卡：
  · xLAM-2-8B fp16 推理需 ~16GB ✗ 与 vLLM 7B 抢显存 ⚠
  · Hammer2.1-7B fp16 ~14GB ⚠ 勉强 ✓ 但要停我们的 7B ✓
  · GGUF 量化版 ✓ 可跑（ollama ✓）但走不了 vLLM 的 function-calling schema ⚠
⇒ T-0 的**可执行性打折** ⚠ 但**至少要在 HF 上核对**是否真有更优方案 ✓
⇒ 若硬件跑不动 ⇒ 直接进阶段 2 ✓（记录下来 ✓）
```
