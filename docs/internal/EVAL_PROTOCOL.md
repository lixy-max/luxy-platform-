## 三、指标定义（5 个工具指标 + 3 个基础指标）

| 指标 | 定义 | 数据来源 | 越好 |
|---|---|---|---|
| **工具选择命中率** | 期望工具集合任一被调用 ⇒ 1 ✓ 否则 0 ✓（"或"语义 ✓ 同 drill_score） | `ui_cards` / `exec_tools` vs 任务定义 `类目` | 高 ✓ |

| **报错修复率** | 有报错的任务里，报错之后又成功 ⇒ 1 | `ui_cards` 顺序 ✓ | 高 ✓ |
| **调用轮数** | 工具调用次数 | `ui_cards` / `exec_tools` | **低** ✓（效率 ✓） |
| 任务 ok 率 | 原判分器口径（60 分制满分 = ok） | `runs.jsonl ok` | 高 ✓ |
| 耗时 | `elapsed_s` | ✓ | 低 ✓ |
| 总分 | `drill_score.py` 60 分制 | ✓ | 高 ✓ |

## 四、标准流程（★ 必须按顺序 ✓）

```bash
# 0. 确认服务
curl -s http://127.0.0.1:8001/health   # 200 ✓
curl -s http://127.0.0.1:8000/v1/models # 200 ✓

# 1. 环境快照（before ✓ 原则三 M4）
python scripts/eval_env.py snapshot --label before_<实验名>

# 2. 跑臂 A（base ✓ 原则三 M3）
#    （用 drill 跑 eval32 的 32 条 · tag 如 e32_off）

# 3. 跑臂 B（+LoRA ✓）
#    （同 32 条 · tag 如 e32_on）

# 4. 环境快照（after ✓）
python scripts/eval_env.py snapshot --label after_<实验名>

# 5. 漂移检查（必须 0 变化 ✓ 否则不可比 ⚠）
python scripts/eval_env.py diff before_<实验名> after_<实验名>
#   ✅ 环境无变化 → 继续
#   ⚠ 有变化 → 报告里必须说明 ✗ 或还原后重跑

# 6. 工具指标配对比较（★ 主指标 ✓）
python scripts/tool_metrics.py --runs <runs.jsonl> \
  --eval-set docs/EVAL_SET_32.json --compare e32_off e32_on

# 7. 判分器（辅助 ✓ 60 分制）
python scripts/drill_score.py --runs <runs.jsonl> --compare e32_off e32_on
```

## 五、判定标准（写死在流程里 ✓）

| 条件 | 结论 |
|---|---|
| n ≥ 30 ✓ **且** 环境漂移 = 0 ✓ **且** \|t\| > 2 ✓ | **显著提升/退化** ✓ 可以下结论 |
| n ≥ 30 ✓ 但 \|t\| ≤ 2 | **无显著差异** ✓ 照实说 ✗ 不许美化 |
| n < 30 ✗ | **只报差** ⚠ 不下显著结论 ✗（h322 的教训 ✓） |
| 环境漂移 > 0 ⚠ | **不可比** ✗ 必须说明或重跑 ✗ |
