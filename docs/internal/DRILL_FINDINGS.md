## F6 ★ 演练方法教训：必须在【克隆配置】上跑，不能动默认配置 ✗
- 现象: part1 跑完后 `workflow_config.json`（**发布的默认配置** ✗）被改了：
  P1-07「那个没用上的空节点删了」→ 真删了节点 ✗（连"检索节点"都删掉 ⇒ 触发内置测试失败 ✗）
- 处置: `git checkout HEAD -- workflow_config.json` 还原 ✓
- ★ 教训（part2 必须改）:
  1. 演练开始前先 `create_workflow_config` 克隆一份（如 `workflow_config_drill_p1.json` ✓）
     并用 `use_workflow_config` 切过去 ⇒ 所有节点编辑都落在克隆件上 ✓
  2. 跑完把克隆件删掉 ✓（或保留作证据 ✓）
  3. 任何"删/改默认配置"的演练，都要先确认当前编辑目标是克隆件 ✓
- 附带发现: 危险操作确认框**不会**阻止"删节点"这类真实改动 ✓
  （它只是确认 ✓ 演练口径是允许 ✓）⇒ 所以隔离必须靠"克隆配置"，不能指望确认框 ✓
