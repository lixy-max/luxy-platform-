# 前端信息架构调整方案（对话优先 + 工具二级页 + 底座管理下移）

> 目标：**进去直接是对话界面**；布局调优；历史/工作流/LoRA 训练/知识库收进二级页面「工具」；
> **模型底座管理**作为**子目录**并入对话界面的模型选择。底座是**全局生效**，兼容性单列一节。
> 现状基线：单文件 `webui/index3.html` **4861 行 / 232 KB**；后端 612 测试 / 前端 94 项检查。

## 1. 目标信息架构

```
┌─ 一级：对话（默认落地）───────────────────────────────┐
│ 左：会话列表(可折叠) │ 中：消息区(核心) │ 右：上下文/参数(可折叠) │
│                                                     │
│ 顶部：会话标题 · [模型选择 ▾] · 上下文用量徽标         │
│       模型选择 ▾ ── ① 当前模型（底座 / LoRA，本会话） │
│                  └ ② 底座管理 ▸（全局，二级子菜单）    │
│ 底部：输入区（固定，多行、Enter 发送、拖拽上传、/ 指令）│
└─────────────────────────────────────────────────────┘
        │ 右上角「工具」入口
        ▼
┌─ 二级：工具 ─────────────────────────────────────────┐
│ [🧩 工作流] [📜 历史] [🚀 LoRA 训练] [📚 知识库] [⚙️ 系统设置] │
│  · 二级页用「返回对话」回到一级；用 sub-nav 在工具间切换 │
│  · URL 带 hash：#/chat、#/tools/workflow、#/tools/kb … │
└─────────────────────────────────────────────────────┘
```

**要点**
1. **一级只有一个**：对话。其余全部二级（工具），二级页有统一的"← 返回对话"。
2. **底座管理不再是独立页**，而是模型选择器的**二级子菜单**（见 §3 兼容性）。
3. **系统设置**也收进工具（它原本是平级 tab），但**保留**其中"底座模型路径"字段的说明（避免与底座管理重复）。
4. **hash 路由**：`#/chat`（默认）、`#/tools/<name>`；刷新/前进后退都能回到原页。

| 区域 | 调优内容 |
|---|---|

| 消息 | 用户/AI 气泡区分；**工具调用卡片**（可折叠，显示工具名/参数/结果摘要）；代码块带复制；错误用 `--c-danger` 令牌 |

| 响应式 | <1100px 自动收起右栏；<760px 会话列表变抽屉 |

## 3. 底座管理下移：**兼容性分析**（本方案最关键的一节）

底座（`--model`）是 **vLLM 进程级**、**全局唯一**的状态，切换 = **停进程 → 加载新模型 → 重启**（实测就绪约 30s，32K 上下文更久）。因此把它放进对话的模型选择器**会显著降低误触成本**，必须配套守卫。

| # | 影响 | 严重度 | 守卫措施 |
|---|---|---|---|
| C1 | 误触切换 → vLLM 重启，**正在跑的工作流全部失败** | 高 | 入口放**二级子菜单**；确认框写明影响；切换前查 `GET /tasks`，有在跑任务则**禁止** |
| C2 | **训练进行中**时切底座 → GPU 冲突 / 训练中断 | 高 | 查 `GET /training/list`：训练中则菜单项**置灰**并提示"训练中，不可切换" |
| C3 | 切换后**已加载 LoRA 全部失效**（进程重启） | 中 | 切换成功后清空对话的 LoRA 选择并提示；引擎侧已有幂等加载 + 快照失效重载（§AA），无需改 |
| C4 | **底座与 LoRA 强绑定**（hidden 维度/架构不同则不可用） | 高 | 模型选择器的 LoRA 列表按**当前底座过滤**：`GET /loras` 已返回每个 LoRA 的 `compatible` ✓ 直接用；不兼容项置灰并注明原因 |
| C5 | 切到不兼容底座（如 Qwen2.5-7B hidden 3584）后，**4B 系列 LoRA 全不可用**（extract_v2、dimensions_v1/v2、paper_analyzer_v5/v6…） | 高 | 子菜单里**显式列出会失效的 LoRA 数量**；确认框二次确认 |
| C6 | **工作流节点绑定 LoRA** → 切底座后工作流本地节点会失败 | 中 | 切换前扫描 `workflow_config.json`（及全部 `workflow_config_*.json`），提示"N 个节点绑定了 LoRA，切换后需调整"；引擎预检会在运行时**快速拒绝**（不会静默出错 ✓） |
| C7 | Agent 工具 `switch_model` 契约（`vllm:base` 等）已被提示词文档化 | 中 | **UI 重构不动工具契约**；只改 UI 层表达 |
| C8 | 前端 94 项检查依赖现有 tab 结构 | 中 | 同步更新 `tests/frontend/run.js` 断言；每步迁移后前后端两套基线都必须全绿 |
| C9 | 旧书签/深链（无 hash） | 低 | 无 hash → 落到 `#/chat`（可接受，符合"进去直接是对话"） |
| C10 | 训练期间 vLLM 是**停的**（实测）→ 底座菜单此刻本就不可用 | 低 | 菜单顶部显示实时状态：`vLLM 运行中 / 训练占用 / 未知`（`GET /vllm/status` ✓ 已有） |

**结论**：**可以做，但不要做成"下拉里直接切换"** ✗。正确形态是：
> 模型选择器 = 一级（**本会话用哪个模型**：底座 or 某个 LoRA）
> 其二级子菜单 = **底座管理（全局）**：当前底座、可用底座列表、切换按钮（带 C1/C2/C5/C6 守卫）、显存与状态、重启。
> 即：**"选模型"是会话级、频繁的操作；"换底座"是全局级、危险的操作** —— 用一个控件的两级来表达，既满足你的要求，又不把危险操作放到一级。

## 4. 迁移步骤（增量、每步可回滚、测试门禁）

| 步 | 内容 | 验收 | 预估 |
|---|---|---|---|
| **M1** | 一级/二级导航骨架：默认页改 `chat`；新增「工具」二级页，装入 工作流/历史/LoRA/知识库/系统设置（**先只是搬家**，不改内部逻辑） | 前端 94 项 + 后端 612 项全绿；5 个页面功能逐一点过 | 2-3 h |
| **M2** | hash 路由（`#/chat`、`#/tools/*`）+ 二级页「← 返回对话」+ 面包屑 | 刷新/后退保持在原页 | 1-2 h |
| **M3** | 对话页布局重构（三栏 + 吸顶 + 固定输入区 + 工具卡片 + 空态 + 进度反馈） | 长会话滚动/折叠/上传/快捷键可用 | 3-4 h |
| **M4** | 底座管理并入模型选择器二级菜单 + **C1/C2/C4/C5/C6 守卫** | 守卫逐条手工触发验证（含"训练中置灰"） | 2-3 h |
| **M5** | 美化：令牌统一、暗色模式、动效、响应式 + 新增前端测试（导航/守卫） | 两套测试 + 视觉走查 | 3-4 h |
| | **合计** | | **约 11-16 h** |

**为什么分 5 步而不是重写**：单文件 4861 行 + 全局状态 + 94 项前端断言 ✗ 一次性重写会把"能用的功能"和"要改的结构"混在一起，出问题无法定位 ✗。逐步搬家的做法每一步都能独立回滚 ✓。
