## 三、诚实评估（★ 按评测协议 ✓）

### 3.1 支持的陈述

在**本次设置**下：
1. **Hit@5 从 0.80 → 0.90（+10 个百分点）** ✓ — A 组更好 ✓
2. **A 独中 3 题、B 独中 1 题** ✓ — 方向一致 ✓
3. **A 组块更小（263 vs 432 字符）且 100% 带 section 元数据** ✓ — 这是差异的来源 ✓

### 3.2 不支持的陈述（★ 必须说清 ✗）

1. ✗ **"显著提升"** — **n=20 < 30** ⇒ 按 `EVAL_PROTOCOL.md` **不下显著结论** ✓
   - MRR/nDCG 差 0.005 ⇒ **可能在噪声范围内** ⚠
2. ✗ **"清洗有效"** — 测试文档是**干净 Markdown** ✓ → **噪声删除 = 0** ✗
   - ⇒ 本实验的 A/B 差异**只反映结构感知切块** ✓ 不反映清洗 ✓
3. ✗ **"对 PDF 文档也有效"** — **未测试 PDF** ✗（本项目 docs 全是 md）
4. ✗ **"提升了答案质量"** — 关键词命中率 0.217 vs 0.200 ⇒ **几乎无差** ⚠

### 3.3 关键限制

| # | 限制 | 影响 |
|---|---|---|
| **1** | **n=20 < 30** | 不能下显著结论 ✗ |
| **2** | **测试文档干净**（无 PDF 噪声 ✓） | 清洗环节**未发挥** ✗ |
| **3** | 只测了 **10 个文档 / 56KB** | 规模小 ⚠ |
| **4** | 只用了 **1 个 embedding 模型** | 换模型结论可能变 ⚠ |
| **5** | 用了 **1 个 LLM 出题 + 回答** | 换模型可能变 ⚠ |
| **6** | 单次运行（**无多重复** ✓ 同 P-54 问题 ⚠） | 无法估计运行间方差 ⚠ |

## 四、结论（严格限定 ✓）

```
在【本项目 10 个 Markdown 文档 + bge-small-zh + Qwen2.5-7B】的设置下：
  · A（结构感知切块）比 B（默认切块）的 **Hit@5 高 10 个百分点**（0.90 vs 0.80）✓
  · MRR / nDCG / 关键词命中率 **差异在 0.005-0.017 之间** ⚠ 大概率噪声
  · **样本量 n=20 < 30 ⇒ 不下显著结论** ✗
  ⇒ **方向值得继续验证 ✓ 但现在还不能说"清洗能显著提升检索"** ✗
```
