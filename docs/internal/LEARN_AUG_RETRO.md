## 四、价值验证：**从未做过 A/B** ✗（最关键的缺失）

```

## 七、结论

```

## 九、改造清单（与 ROADMAP 第 30~33 项对齐 ✓）

```
1. 入口收窄: 只把【云接管且最终成功】的轨迹入库 ✓（失败/免责一律不进 ✗）
   判据: 云的最终答案里没有"我无法/请提供" + 本轮至少 1 个成功工具 ✓
2. 去重: 同问句只留最新 ✓（已做 ✓）· 加语义近重复检测 ✓（同任务问法不同 ⇒ 合并 ✓）
3. 切分: 1 经验 = 1 chunk ✓ · overlap = 0 ✓ · 块首回填问句 ✓（P-23b ✓）
4. 质量闸门 v2: 工具计划为"无" ⇒ 只允许入"对话经验"库 ✗ 不进 agent 指导库 ✓
5. 转云阈值: 零工具直接转云 ✗ ⇒ 改为"本地先尝试 1 轮只读工具"✓（可降 57% 接手率 ✓）
6. ★ A/B 验证（关键 ✓）: 同 20 条任务 × {有检索, 无检索} ⇒ 比成功率 ✓
   通过标准: 有检索 +5pp ✓ 否则回滚改造 ✓
```
