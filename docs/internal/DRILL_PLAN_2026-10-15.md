## 3. 判分方案（问题8 的判断）

### 3.1 两段制（总分 100）
```
第一段 · 机器可判（60 分，脚本 100% 自动 ✓ 无争议）
  · 产物存在性（文件/配置/数据集/adapter ✓）
  · 真的改对了吗（docx/xlsx 可解析 + 目标字段/段落确实变化 ✓）
  · 配置 validate 是否通过 / 节点是否真的写进配置
  · LoRA 是否有 adapter 且可挂载 / 知识库块数是否真的增长
  · 检索是否真的能命中新内容（固定问法 ✓）
第二段 · 判官逐条（40 分，云端判官 ✓）
  ★ 判官【不整体打分】，只回答: 「任务里写明的第 k 条要求，满足了吗？证据是哪段？」
     → 每条任务在清单里预写 1~5 条「可引用证据的要求」✓（写任务时同时写）
     → 输出 {requirement_id, met: bool, evidence: "原文片段"} ⇒ 连续分（GUIDE 第三部分纪律）
```

### 3.2 防「假高分」
```
· 判官必须给出【证据片段】才允许判 met=true ✓ 无证据不给分
· 抽检 20% 任务由 lead 人工复核（重点查判官判「满足」的 ✗ 这类错最危险）
· 判官 vs 抽检 不一致率 > 15% ⇒ 重写 rubric 并重判该批
```

### 3.3 分档与达标线
```
≥85 优秀 ｜ 70~84 合格 ｜ 50~69 勉强 ｜ <50 不合格
「符合要求」= ≥70 分
本批达标线:
  · part1 一次成功率 ≥ 70%
  · 走云接手后的合格率 ≥ 80%
  · v2 相对 v1（同一 20 条）提升 ≥ 5 个百分点
  · 判官-抽检不一致 ≤ 15%
```
