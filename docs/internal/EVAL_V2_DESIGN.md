### 问题 ③ **泄题风险 —— 实测澄清：不存在 ✓**

`docs/EVAL_BASELINE_FULL.md` 曾说：

**① 驱动层不泄题 ✓**

**⇒ 结论：泄题风险不存在 ✓**（EVAL_BASELINE_FULL 那句是**对文档的误读** ✗ —
   类目字段是**给判分器的** ✓ 驱动从不传它 ✓）

## 二、V2 设计：三个针对性修复

| # | 问题 | 修复 |

### 2.1 任务选择（105 → 35 条 · 实测评分 ✓）

**区分度评分规则**（每项加分 ✓）：
```
+3  状态依赖（克隆 / 副本 / 别碰默认 / 先复制）
+2  多步（先…再…然后 / 多环节）
+2  类目 ≥4 个工具（复杂度）
+2  不可能任务（边界）
+1  精确参数（数字 / 文件名 / 引号内容）
+1  验收点 ≥4 条（可机器判分）
-5  原话里出现工具名（泄题 ✗）
```

**评分分布（105 条实测）**：
```
高潜力（≥5 分）: 12 条 ✓
中潜力（2-4）:   21 条
低潜力（<2）:    72 条 ✗ ← 这些就是天花板的来源
```
