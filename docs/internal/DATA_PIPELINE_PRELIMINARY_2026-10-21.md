```
效果: 清洗 660→507（-23% ✓）· 噪声残留 3→**0** ✓ · 垃圾块被过滤 ✓
```

### 修复 2：英文学术 PDF 噪声（NOISE_PATTERNS 补 9 类）
```
实测症状: 831 字符学术文档 → 只清 9% ✗ 残留 9 类 ✗
  残留: Downloaded from / doi.org / Received: / Corresponding author /
        Figure 1. / Table 1. / [1] Smith / [2] Jones / References
修: 补 下载水印/投稿日期行/通讯作者行/图表标题/参考文献条目/
       参考文献标题/基金资助/版权许可/CC-BY ✓
效果: 清洗 831→337（**-59%** ✓）· 噪声残留 9→**0** ✓ · 正文 0 误伤 ✓
```

### 修复 3：精修 3 处残留（实测才发现的 ✗）
```
① "Corresponding author. Email: a@b.com" 一行两信息 ⇒ 原 pattern 匹配不到 ✗
② "## References"（markdown 标题）⇒ 原 pattern 没允许 # ✗
③ 纯邮箱行 / 中文"通信作者" ✗
效果: NOISE_PATTERNS 最终 **11 → 28 个** ✓ 两类合成样本全通过 ✓
```

### 修复 4（★ 真实 PDF 才暴露的 bug）：切块超长
```
实测症状: 3 篇真实 arXiv PDF → 最大块 **5,373 字** ✗✗（目标 500 ✗）
根因: _split_by_para_sentence 里「单句 > chunk_size ⇒ buf 直接超长」✗
      真实 PDF 的表格/公式/参考文献经常一大段无句末标点 ✗ ⇒ 整段当 1 句 ✗
修: 单句超长先硬切成 chunk_size 片段 ✓
效果: 8000 字无标点 → **16 块 × 500** ✓
      3 篇真实 PDF → **736 块（51~500 ✓）** 质量分 5.17→**5.62** ✓
```

## 三、⚠ 样本量不足 —— 已知局限（**这正是"后续加大"的原因**）

| 局限 | 影响 | 后果 |
|---|---|---|
| **仅 3 篇 PDF** ⚠ | 同领域（arXiv 论文）| 不代表中文/技术/人文/法律文档 ✗ |
| **仅 15 题** ⚠ | n=15 ⇒ 1 题变化就 6.7pp | **无法做显著性检验** ✗ |
| **题目偏硬** ⚠ | 大量具体数字/图表数值 | 即使上下文对也"命中不了" ✗ |
| 只测检索层 ⚠ | 没测「LLM 用检索结果答题准确率」| 离真实用途还差一步 ✗ |
| 云端模型 ≠ 本地 ⚠ | deepseek-chat 远强于本地 7B | 结论迁移需谨慎 ⚠ |
