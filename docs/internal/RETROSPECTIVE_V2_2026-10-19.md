## 四、做错了什么 ✗（诚实版）

### ❌ 错误 1：**项目定位错了一整个阶段**（最严重 ✓）
```
现象: README 写"云边协同的论文分析工作台"✗ 实际是"模型训练平台"✓
后果: 大量功能围着"论文分析"做 ✗ 但用户根本不需要 ✗
根因: **我没有读需求就开干** ✗ 用户的真实目标（训练自己的模型）被我忽略了 ✗
代价: 至少几天的工作废掉 ✗
现在: P-72 已修 ✓ README 重写 ✓ 但**代码里的"论文"痕迹还在** ✗
```

### ❌ 错误 2：**"追能力"的方向错了**（代价最大 ✗）
```
4 轮 A/B 全部证明: LoRA 对 7B/14B 的"能力提升"无效 ✗
  · v3-2-0: 40 条 格式错位 ⇒ 判分 -0.1 ✗
  · v3-2-1: 1054 条合成 ⇒ 判分 -0.5 ✗（合成数据完全无效 ✗）
  · v3-2-2: 278 条真实 ⇒ +8.0 但 base 漂移 -7.5 ⇒ 实际无效 ⚠
  · v3-3-0: 435 条真实新 schema ⇒ -3.1 ✗（"显著轮数下降"是离群值假象 ✗）
根因: 没先读文献 ✗ 凭直觉认为"数据多就能提升" ✗
代价: **几十小时训练 + 几小时评测** ✗
现在: 转为"风格/行为/格式"定位 ✓ 但**还没做出一版真正有用的 LoRA** ✗
```

### ❌ 错误 3：**数据策略反复摇摆**
```
40 → 1054（合成 ✗）→ 278（真实 ✓）→ 435（更真实 ✓）
每次换方向都浪费一次训练 ✗
根因: 没先看 L01/L02 的数据量规律 ✗ 也没先看 L12（原始轨迹入库会降质 ✗）
```

### ❌ 错误 4：**评测设计有严重缺陷**（差点得出错误结论 ✗）
```
· 单次跑就下结论 ✗（P-54 伪重复 ✗）
· 环境漂移 6 处还硬比 ✗（v3-3-0 A/B ✗）
· "调用轮数 -6.22 显著"是【离群值假象】✗（我一开始还当真了 ✗ 后来逐任务查才推翻 ✓）
根因: 先跑实验后补方法 ✗ 顺序错了 ✗
```

### ❌ 错误 5：**多次严重误操作**（我自己造成的 ✗）
```
| 事故 | 后果 |
|---|---|
| 同一条采集命令启动两次 ✗ | 轮次重复 50 条 ✗ |
| 用"按启动时间杀进程"猜 ✗ | **采集全停 5 小时** ✗✗ |
| 补丁脚本 sys.exit 在写文件之前 ✗ | 改动静默丢失 ✗ 2 次 ✗ |
| /training/start 缺校验 ✗ | 假任务 + vLLM 被停不重启 ✗ |
| 测试 /training/start 用了"合法"payload ✗ | 真启动了训练 ✗ |
⇒ **每一条都写进了台账（P-87/88/89）✓ 但代价是真实时间** ✗
```

### ❌ 错误 6：**文档膨胀**

87 个文档 / 630 KB ✗ 其中 PLATFORM_ISSUES 1,828 行 ✗

## 五、关键教训 → 固化为规则 ✓

| # | 教训 | 规则（已写入原则 ✓） |
|---|---|---|
| **1** | 定位错代价最大 | **先读需求再写代码** ✓ 用户说什么就是什么 ✗ 不要自己推测 |
| **2** | 文献先行能省几个月 | **调研先行** ✓ 任何"提升"目标先查 ≥2 篇文献 ✓ |
| **3** | 先找现成再训练 | **先找不训** ✓ 模型→LoRA→API→提示词→训练（训练最后 ✓） |
| **4** | 评测口径先行 | **先定指标再跑实验** ✓ 单次跑不下结论 ✗ 环境必须冻结 ✓ |
| **5** | 用户经验 > 我的推断 | **用户的实际操作观察优先** ✓ 我的推测必须标注"待验证"⚠ |
| **6** | 别凭直觉下因果 | **任何"X 导致 Y"必须有对照实验** ✓ 否则只说"观察到"⚠ |
| **7** | 补丁脚本要幂等 | **每处改动立刻写文件** ✓ 不用 sys.exit 丢进度 ✗ |
| **8** | 杀进程要精确 | **按 PIDs + 命令行核对** ✓ 不用"启动时间"猜 ✗ |
| **9** | 文档写结论 | **文档 = 决策 + 依据** ✓ 不是过程流水账 ✗ |

## 六、核心问题：为什么模型没提升？

### 诚实的因果分析

```
① **PET 天花板**（L02 ✓）: LoRA 只能学"风格偏移"✗ 学不到"能力"✗
   ⇒ 这是**结构性限制** ✓ 不是我们做得不好 ✗

② **数据量不足**: 435 条 vs 文献建议 1000-2000 ✓ 差 2-5 倍 ✓

③ **数据质量**: 真实 ✓ 但轨迹本身"平庸"⚠（Agent 只是调工具 ✓ 没有"高水平示范"✗）
   ⇒ L12 教训: 原始轨迹直接入库会降质 ✗ 需要清洗/蒸馏 ✓

④ **评测集太简单**: base 就 100% ok ✗ ⇒ 天花板被评测集掩盖 ✗
   ⇒ "接近上限"部分是评测集造成的 ✗ 不是纯模型上限 ✓

⑤ **没有做蒸馏**: T-2 计划了但没做 ✗ ⇒ 数据里没有"专家示范"✗
```

### ⇒ 结论：**LoRA 路线在"能力"上已到上限** ✓ 但**没试过"知识/示范"路线** ⚠
