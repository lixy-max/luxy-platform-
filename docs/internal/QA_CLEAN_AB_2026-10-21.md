# 清洗 vs 未清洗 知识库 · QA 对照实验（2026-10-21）

> **问题**：清洗过的知识库 vs 未清洗，问答时**准确与效率**差多少？
> **数据**：3 篇真实 arXiv PDF（286,311 字符）→ 2 个 KB
> **模型**：云端 deepseek-chat（两臂同模型 ✓ 公平 ✓）
> **题目**：15 题（从清洗后 chunks 生成 · 问细节 · 带关键实体 ✓）

---

## 二、结果（客观指标优先 ✓ 不靠主观判分）

| 指标 | 未清洗 | 清洗 | 变化 | 判定 |
|---|---|---|---|---|
| **实体命中率** | 42.6% | **43.7%** | **+1.1pp** | ⚠ 提升很小 |
| 全命中题数 | 1/15 | **2/15** | +1 | ⚠ |
| **噪声占比** | 3.7% | **1.0%** | **-2.7pp（-73%）** | ✅ 显著降低 |
| **上下文长度** | 1,546 字 | **1,181 字** | **-365（-24%）** | ✅ 显著减少 |
| **检索耗时** | 1,041 ms | **369 ms** | **-671 ms（快 2.8 倍）** | ✅✅ 大幅提升 |

---

## 三、★ 核心结论（诚实 ✓）

### ✅ 清洗的价值在「效率与质量」✓
```
· 检索**快 2.8 倍**（1041ms → 369ms ✓✓）
· 上下文**省 24%**（1546 → 1181 字 ✓）
· 噪声**降 73%**（3.7% → 1.0% ✓✓）
⇒ 这三项都是**实打实的收益** ✓ 且工程价值明确 ✓
   （快 2.8 倍 = 用户等待时间少 2/3 ✓）
   （上下文省 24% = 同样窗口能放更多历史/工具 ✓）
```

### ⚠ 但对「检索准确率」提升很小 ✗
```
· 实体命中率 +1.1pp（42.6% → 43.7% ✗ 不显著 ⚠）
· 全命中只从 1/15 → 2/15（n=15 太小 ✗）
⇒ 与之前 KB A/B 的结论**一致** ✓:
   「清洗主要提升质量指标，对检索准确率影响有限」✓
   （docs/KB_AB_REPORT_2026-10-20.md 也是这个结论 ✓ 交叉印证 ✓）
```

### 为什么命中率整体都低（42-44% ✗）
```
题目太硬 ⚠: 15 题里有大量「具体数字/图表里的模型名/表格数值」✗
  · "GPT-5.4-nano 对应的三个数值"
  · "Llama-4-Maverick 的三个数值分别是多少"
  · "在 HIDDEN/URL-ONLY/ORIGINAL 三种条件下的 τ 值范围"
⇒ 这类题目**即使上下文正确也难"命中实体"** ✗
  （因为表格数据在 PDF 提取时被压成文本，顺序混乱 ✗）
⇒ 这批题更适合测「检索精度」，不适合测「清洗价值」⚠
```

## 五、局限（诚实 ✗）

```
✗ n=15 太小 ⚠（只是首轮探索 ✓）
✗ 题目类型偏「硬」（具体数字/图表 ✗）⇒ 对清洗不敏感 ⚠
✗ 只有 3 篇 PDF（同领域 arXiv 论文 ⚠ 不代表所有文档 ✓）
✗ 只测了检索层（没测「LLM 用检索结果答题的准确率」✗ 那一步要更多调用 ⚠）
✗ 云端模型 ≠ 本地模型（deepseek-chat 能力远强于本地 7B ⚠）
   ⇒ 结论迁移到本地模型需谨慎 ⚠
```
