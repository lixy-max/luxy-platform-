## 1. 验收点可判性

### 1.1 A 类 · 硬伤：对象/指代无落点（10 条 ⇒ 判不了"是不是听懂了"）

**根因**：DRILL_PLAN §2 规定"一条任务一次对话、不复用历史"。但下列 10 条的原话/验收点依赖**上一轮的产出**，而新会话里没有"上一轮"。结果：模型只能猜一个对象，或正确地反问——但验收点 1 写的是"指代解析正确 ⇒ 必须落到某个具体 id"，**两种行为都判不过**。

| 任务 | 问题（无落点的对象） | 改法 |
|---|---|---|
| **P1-05** | "给它加个节点"——"它"= 哪个工作流？新会话无前序 | 原话补对象：「给 **paper_edit 那个**工作流加个节点…」；或标为 G2 组内紧跟 P1-01 跑，并在验收点 1 写明"目标配置 = P1-01 产出的那份（名字：___）" |
| **P1-06** | "刚才加那个节点"——依赖 P1-05 | 二选一：① 并入 P1-05 成一条（两件事一句话，符合用户口气）；② 保留但标"依赖 P1-05"，验收点 1 改为"能报出所改节点 id，且该 id ∈ P1-05 新增节点集合" |
| **P1-07** | "那个没用上的**空节点**"——既没指明哪个，也没定义"空" | 原话自足化：「把**克隆件里那个没有 output 的、名字叫 debug 的**节点删了」；验收点加"删除前给出候选节点清单与判定依据" |
| **P1-09** | "刚才那个跑完没"——依赖 P1-08 的 task id | 标"依赖 P1-08"；或原话改为「**刚才跑的那个论文分析**跑完没」（仍靠 P1-08，故仍需标依赖） |
| **P1-10** | "把结果导出来给我"——"结果"未指哪个 | 标"依赖 P1-08/09"；验收点 1 改为"报出所导出的 result 文件名/任务 id，且与 P1-08 的 task 对应" |
| **P1-19** | "上一轮那个工作流结果"——同上 | 标"依赖 P1-10/11"；或原话指名：「把 **P1-10 导出的那份** 做成训练数据集」 |

| **P1-40** | "刚才那个流程不错"——依赖 P1-39 | 标"依赖 P1-39"；验收点 3 改为"步骤与 P1-39 实际运行的流程逐条一致（步数+顺序+工具名）" |
| **P1-43** | "这个不对，重做"——"这个"= 上一条产出；新会话无上一条 | ① 若坚持"信息极少"的压测意图：把验收点 1 改成"**若无前序产出，应先追问 1 个澄清问题**"（这是可判的：轨迹里出现提问且未误改文件）；② 若要测重做：并入一条有产出的任务之后 |
| **P1-44** | "**文档**里那个 26b"——哪个文档？"历史章节"也没定义 | 原话点名文件：「把 **docs/HANDOVER.md** 里那个 "26b" 全换成 "27b"，只改**「历史」那一节**」；验收点 1 的"命中清单"才有基线可核（★ 必须用副本文件，见 §2） |
