## 四、结论（严格按 EVAL_PROTOCOL ✓）

### 4.1 支持的陈述

在**本次设置**下（n=30 ✓ device=cuda:0 ✓）：

1. **结构感知切块带来显著提升** ✓✓
   - hit@5 **+10.0 个百分点**（0.867 → 0.967）
   - **MRR +16.1 个百分点**（0.678 → 0.839）
   - ⇒ **这是本实验最大的效应** ✓✓

2. **规则清洗有效但增益较小** ✓
   - 噪声残留 **60% → 0%** ✓（清洗本身完全有效 ✓）
   - hit@5 **+3.3 个百分点**（0.967 → 1.000）
   - MRR **+0.3 个百分点** ⚠（几乎无差）

3. **答案关键词命中率（kf_rate）基本不变** ⚠
   - A/B/C 分别 0.296 / 0.300 / 0.289
   - ⇒ **检索提升了，但答案质量没有同步提升** ⚠
   - **可能原因**：本地 7B 模型不能很好利用更好的检索结果 ✗ / 关键词匹配指标太粗 ⚠

### 4.2 不支持的陈述

1. ✗ **"清洗能显著提升检索"** — MRR 只 +0.3pp ⚠，且**未做 t 检验**（脚本未保存逐题数据 ✗）
2. ✗ **"能提升问答质量"** — kf_rate 无变化 ⚠
3. ✗ **"对 PDF 文档有效"** — 用的是**人工注入噪声** ⚠ 不是真实 PDF ✗
4. ✗ **"可以推广到其他 KB"** — 只测了 1 个语料 / 1 个 embedding / 1 个 LLM

### 4.3 限制

| # | 限制 |
|---|---|
| 1 | **n=30**（刚好达协议线 ✓ 但不大 ⚠） |
| 2 | **单次运行** ✗（无多重复 ✗ 无法估计方差） |
| 3 | **未做 t 检验** ✗（逐题数据未保存 ✗） |
| 4 | **噪声是人工注入的** ⚠（真实 PDF 噪声更复杂） |
| 5 | 单 embedding 模型 / 单 LLM |
