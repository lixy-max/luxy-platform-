## 1. 任务定义（为什么不是"意图分类"）

失败挖掘（209 条真实轨迹）给出的结论是：**卡点不在"听懂类别"，而在"选对动作 + 信息不足时提问"**：
- 「报错/找不到后不换路」19.1% ｜「空产出」15.3% ｜「名字猜错/资源不存在」占比最高的一类
- 成功 vs 失败：调用次数 8.61 → 26.30（3.05 倍）；只读深挖 2.61 → 12.52（4.8 倍）

⇒ 所以样本形态定为 **一句话 → 五元组**（而不是单标签）：

```json
{"intent_type": "<枚举>", "goal": "<一句话>", "constraints": ["禁令/硬要求..."],
 "targets": {"kb|lora|dataset|file|workflow_node|base_model|provider": "..."},
 "missing": ["需要澄清的点"], "should_ask": true|false,
 "plan": [{"tool": "<工作台真实工具名>", "why": "..."}]}
```

- `plan` 只允许**工作台真实存在的 50 个 agent 工具**（生成时用 `agent_kb/_tools.json` 校验 ✓）
- `should_ask=true` 是**一等公民**：名字不在环境快照里、指代不明、动手代价高 ⇒ 必须先问/先 list
- `constraints` 必须承接用户禁令（"别烧云"、"不要进错库"、"不改原配置"）

## 2. 数据配方（核心：以**你的口气**为锚，不编教科书句式）

### 2.1 种子（已落地）
`data/user_voice/seeds.jsonl` —— **23 条从真实对话转录的原话**，逐条人工标注了期望语义 + 风格标签。
覆盖的真实现象：
| 现象 | 例（你的原话） |
|---|---|
| 长句无标点、逗号连发 | "现在这个工作台有一个较完整的链条…验证这个链条完整性…" |
| 极简/单字母指代 | "a"（=选方案 A）、"已经起了"、"秒没了，" |
| 否定纠错开场 | "不是，那你又搞错了啊，用lora 平台agent 功能…" |
| 情绪/反问当断言 | "有些难绷了…项目文档是不是还没跟进" |
| 错字与自更正 | "glm2.7" → "不是glm2，7我打错了，叫glm4.7flash" |
| 中英混写、空格替下划线 | "入库入agent use 不要进错了" |
| 一句多要求 | "再来100条任务，继续训练，一定要评估是否都有结果，并且符合要求" |
| 授权与边界 | "你可以把一些边际任务分配给他们做" |
| **题眼：以我的口气为准** | "你可以去看看我给你提出任务的口气" |

### 2.2 自动扩样（今晚已做，离线确定性、不需要 GPU）
`scripts/gen_semantic_dataset.py` 三类扩样，**全部可规则校验**：

3. **多要求连发**（你的典型句式）："先X，然后Y，再Z" → 合并 constraints、拼接 plan
4. **陷阱家族**（19 条）：引用不存在的库/LoRA/文件、纯"那个"指代 ⇒ 期望 `should_ask=true`

## 3. 今晚怎么跑（一条命令）

```bash
# 在 WSL 里，或直接双击桌面「启动工作台.bat」的那套环境里执行：
bash scripts/train_semantic.sh            # 默认: 语义意图 v1 / Qwen2.5-7B-Instruct(fp16) / QLoRA
bash scripts/train_semantic.sh --dry-run  # 只打印将要执行的命令，不动 GPU
```
脚本做的事（按序）：
1. 检查基座**不是** AWQ/GPTQ（否则直接停下并提示 ✗）
2. 生成/刷新数据集（若还没生成）
3. **停 vLLM** 释放显存 → 记录释放前后显存
4. 调 `train_lora.py`（LLaMA-Factory QLoRA，rank/alpha 走项目推荐值）
5. 训练日志落 `training_logs/semantic_intent_v1.log`（可 `tail -f` ✓）
6. 训练结束**自动重启 vLLM**（`auto_restart_vllm=true`）并校验 `/v1/models` 200 ✓

**预计时长**：310 条 × 3 epochs ≈ 1.5~3 小时（单卡 16GB）✓ 正好一夜。

## 4. 明早的流程（纠错 → 清洗 → 入库）

1. **看训练结果**：`training_logs/semantic_intent_v1.log` 的 loss 曲线 + 是否早停；
   产物在 `~/loras/semantic_intent_v1/`（含 adapter）✓
2. **跑留出集评测**：用 13 条留出样本，按三个指标打分（这就是"评估是否都有结果、并且符合要求"的语义版）：
   - **schema 合法率**（能否稳定输出 JSON）
   - **工具名正确率**（plan 里工具必须真实存在且选对）
   - **should_ask 命中率**（该追问的有没有追问 —— 这是本轮最想验证的能力）
3. **人工纠错**（抽 30~50 条，重点看"陷阱"与"多要求"两族）→ 写回 `seeds.jsonl` 或直接修订数据集
4. **清洗**：复用 `scripts/learn_sink.py` 的清洗规则（去绝对路径、去重、丢弃不完整）
5. **入库**：数据集归 `training_data/` ✓；从数据里提炼的**可照做规则**（如"名字不在快照里就先 list 或追问"）
   写成经验型短条目 → 按主题入库（工具调用类 → `agent_use` ✓；答题规范类 → 另建 `qa_standards` ✗ 别混）
6. **接回链条**：把这批规则同时写进工作台 agent 的 system 提示（比 LoRA 更快见效 ✓）

## 5. 更优方案（我的建议：两条腿走，别只训 LoRA）

### 5.1 今晚同时做（零成本、立刻生效）
把下面这条写进 **agent system 提示**（`webui/index3.html` 的 `buildAgentSystemPrompt`）：
```
用户在跟一个已经很熟的助手说话：话短、常无标点、会用"那个/刚才/最新"这类指代、可能打错字，
也可能一句话里塞 2~3 件事。因此：
1. 任何"名字"参数（库/LoRA/数据集/文件/节点）都不要凭记忆猜 —— 先调 list_* 拿真名；
2. 名字在【环境快照】里不存在时，先说明"快照里没有它"并给出最接近的候选，再问用户；
3. 一句话里有多件事时，按顺序全做，别只做第一件；做完逐条回报；
4. 用户说"别烧云/不要进错库/别动原配置"这类禁令，视为硬约束，绝不绕过。
```
⇒ 这条提示**今晚就能提升体验**，而 LoRA 要到明天才可用 ✓

### 5.2 数据层面的"更好的样本形态"（明天做）
- **加"环境反事实"**：同一句话配 4 组不同快照（底座变了/库删了/LoRA 卸载了），
  期望输出随之变化 ⇒ 训出真正的"看环境说话"，而不是背答案 ✓（今晚已放 2 组，明天扩到 4~6 组）
- **加"多轮指代"**：第一轮"列一下库" → 第二轮"用第二个" ⇒ 训指代消解 ✓
- **加"纠正轮"**：用户说"不是，你搞错了" ⇒ 期望先定位上一步做了什么、再给最小修正 ✓
  （这正是本会话的真实交互模式 ✓）

### 5.3 别做的（省时间）
- ✗ 不要把 `agent_use` 的内容拿来当语义训练数据（那是工具调用经验库，混用会互相稀释 ✓）
- ✗ 不要用 AWQ 底座训（见第 0 节）
- ✗ 不要在这一版追求"生成多样性"——**标签可信**比句子花哨重要，多样性留给明早的云/大模型扩写 ✓
