# 轨迹蒸馏自动评分方案 v1（预设）

> 对齐《目标与方向统一 v2.0》B1：**自动评分是否值得蒸馏**（不需要用户逐条判断）。
> 状态：**预设方案 v1**（权重可调，待你确认后固化）。实现：`distill_score.py`。

## 1. 评分公式（0–100，可解释）

| 维度 | 权重 | 含义 | 打分规则 |
|---|---|---|---|
| 成功率 success | 0.30 | 任务是否成功且可验证 | 成功=1；失败=0；未知=0.5 |
| 复用频次 reusability | 0.20 | 同类需求历史出现次数 | 0次=0.2；1次=0.5；2–4次=0.8；≥5次=1.0 |
| 新颖度 novelty | 0.20 | 本地能力/工作流是否已覆盖 | 未覆盖=1.0；已覆盖=0.1；未知=0.6 |
| 可拆解性 decomposability | 0.15 | 能否拆成单步能力/工作流 | 2–6步=1.0；1步=0.5；7–10步=0.6；>10步=0.3；未测=0.4 |
| 轨迹质量 quality | 0.15 | tool_quality A–D + 是否含工具调用 | A=1.0 / B=0.75 / C=0.5 / D=0.2；含工具调用 +0.1 |
| 业务价值 user_value（可选） | 最多 +10 分 | 用户/业务价值加成 | 0–1 × 10 |

**总分 = Σ(维度分 × 权重 × 100) + 业务价值加成，截断到 [0,100]**

## 2. 档位与动作

| 分数 | 档位 | 动作 |
|---|---|---|
| ≥ 70 | **high** | 立即蒸馏：→ 工作流 + 单步 LoRA 数据集 |
| 50–69 | **watch** | 进入候选池，同类再次出现（occurrence+1）或人工点名时蒸馏 |
| < 50 | **skip** | 不蒸馏，仅保留轨迹 |

## 3. 为什么这样设计（对齐你的架构）

- **成功率 + 轨迹质量**是硬门槛：失败/低质量轨迹蒸馏出来的是噪声；
- **复用频次**决定"本地路径"的收益：偶发任务不值得；
- **新颖度**避免重复蒸馏已有能力（本地已有 → 不重复建）；
- **可拆解性**直接服务"高质解耦 LoRA 轨迹"：能拆成 2–6 步的轨迹最适合做成 1 个工作流 + N 个单步能力；
- **业务价值**留出人工/业务加成口（采购/招标类高价值任务加权）。
