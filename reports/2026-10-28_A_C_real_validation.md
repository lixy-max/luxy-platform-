## 二、C 工具路由：真实验证

### 数据
- 来源：`training_data/tool_secretary_v6.jsonl` 历史/真实工具轨迹
- 切分：按 session/trajectory 整条留出，避免同会话泄漏
- C1：每个留出 session 的第一个平台工具决策，150 条
- C2：同一留出 session 的后继步骤（带上下文），137 条
- 工具名经 `tool_name_map.json` canonical 化

### C1 结果（首步决策）
| 指标 | base 7B | C adapter |
|---|---|---|
| JSON 合法 | 0.140 | **1.000** |
| 工具名 exact | 0.000 | **0.4067** |
| 参数 exact | 0.000 | **0.6467** |
| 参数 subset | 0.000 | **0.7733** |
| 名称+参数全对 | 0.000 | **0.2800** |
| 平均延迟 | 6.30s | 1.51s |

### C2 结果（后继步骤）
| 指标 | base 7B | C adapter |
|---|---|---|
| JSON 合法 | 0.3285 | **0.9416** |
| 工具名 exact | 0.1825 | **0.3504** |
| 参数 exact | 0.1533 | **0.3723** |
| 参数 subset | 0.1898 | **0.5693** |
| 名称+参数全对 | 0.1022 | 0.1022 |
| 平均延迟 | 5.03s | 2.73s |

### 结论
- C 在真实轨迹上**格式能力提升明显**：JSON 0.14→1.0、0.33→0.94；延迟减半
- 但**工具名 exact 只有 40.7% / 35.0%，名称+参数全对 28.0% / 10.2%**：远未达到生产可用
- 合成 eval 的 name 0.877 / both 0.705 明显高估了真实泛化
- C2 有上下文时全对没有提升（0.1022→0.1022），说明真实多步路由还不行
- 结论：C 目前只能作为“格式候选”，**不能上线**

这说明之前训练报告的“受控格式能力提升”判断是对的，但 **C 的真实路由能力被合成 eval 放大了**；A 的真实结论更稳。

## 四、最终结论

1. **A 采购清洗 LoRA：真实数据有效**
   - schema/keep/name/spec/category 大幅提升
   - 可进入 shadow + 人工抽查
   - 仍需修 category 约 7% 错误、JSON 约 1% 失败

2. **C 工具路由 LoRA：真实数据只证明了“格式/参数候选”**
   - JSON/延迟改善明显
   - 工具名与完整调用准确率不足，C2 多步没有改善
   - 不能上线，需要真实轨迹重训/更多负例/工具名映射

3. **经验书要写的是这个差异，不是“训练有效”**
   - 合成 eval 只能筛方向
   - 真实验证才能决定上线
   - C 是最典型的“合成高估”案例

## 七、子代理复核修正（2026-10-28，重要）

子代理完整报告：`real_eval_20261028/A_C_真实数据验证报告.md`。以下修正必须覆盖前面的乐观解读：

### A 的“真实”边界
- 109 条来自**同一批 17 个 Excel 的另外几行**，不是换供应商/换年份
- 训练集 2425 行与 catalog 19725 行同源，非图书来源 84%~97% 已被训练覆盖
- 按商品名归一化比对：精确重合 0/109，但 **73/109 共享产品族前缀**（行级留出，不是产品族留出）
- 结论：只能证明“这套表格能跑通”，**不能证明泛化到新供应商/新年份**
- 真错例：price=0 被误判 keep=false（免钉胶、通用区角指示牌）；2 条家具判成户外玩具；1 条 max_tokens 截断（harness 问题，已单列）
- category 人工复核后约 **95.4%**，比自动 92.7% 略高

### C 的关键修正
- **不能用 tool_secretary_v6 做真实 holdout**：758/812 条 human 文本逐字已在 C 训练集里；剩 54 条仅 37 条可用
- 改用 `data/trajectories` 的真实 Agent 轨迹，按 session 分组留出；C1 150 条、C2 137 条；任务文本重合 0
- C1 干净子集 92 条：工具名 exact **45.7%**，名称+参数全对 **32.6%**
- C2：工具名 exact **35.0%**，名称+参数全对 **10.2%**
- **需要填参数的样本，参数全对只有 12.2%（C1）/ 5.1%（C2）**；不需要参数的样本 0.84/0.62
- 训练集工具定义里 `parameters` 几乎全空 → 模型没学过怎么填参数
- 错因：候选集外乱吐工具名（C1 9.3%、C2 35.8% 超出给定 5 个候选）；输出老一代 `paper_lora_*` 名

### 修正后的最终判断
- **A**：在这套 Excel 上真实有效；可作为“同源表格清洗”能力进入 shadow + 人工复核；**不能宣称换供应商/换年份可泛化**
- **C**：JSON/格式归一有效；真实路由工具名只有 4–5 成、参数几乎填不对；**不能上线做路由**，只能当格式归一器
- 早上合成 eval 的 C 指标（name 0.877 / 全对 0.705）与真实差距极大，**不能用于上线决策**
